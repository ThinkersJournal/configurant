kind: SecretAnt adapter crate `configurant-secretant`
---
New workspace crate `configurant-secretant`: `SecretAntSource` implements `SecretSource` over `secretant::SecretReader` (secretant 0.1.5 from crates.io), so `source = "secretant:<name>"` reads a secret from a SecretAnt store at load time (ROADMAP rows 4 and 25, `docs/SECRET-SOURCES.md` slice 4). The store path and unlock are the application's, never the schema's. SecretAnt's four error classes map to `NotFound`, `Denied`, `Unreachable` and `TimedOut`; an entry that is not UTF-8 is `Invalid`; an empty or control-character name is refused before any read. Nothing the store holds reaches an error or `Debug`. Six tests (known-bad first: failure kinds with the canary planted, bad names, environment override, rotation, redaction through `resolve` and `explain`); each of three mutations (Denied mapped to Unreachable, lossy UTF-8, no name check) fails a test. Not checked: a store unlocked with the Windows OS wrap or a recovery key (only the passphrase path is tested).
